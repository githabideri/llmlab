# Hardware Profile: Minisforum BD775i SE

**Configuration:** Minisforum BD775i SE mini-ITX board (bare board, no case or power button; power-on is a front-panel pin bridge), run as a headless single-GPU inference node — RTX 3060 12 GB + 8-core Zen 4 CPU  
**Use Case:** dedicated Strata node for the Qwen3.8-Flash-Next campaign (the engine's own Dockerfile targets "RTX 30/40/50, 12+ GB VRAM" for this model family, so a single 12 GB card is the intended platform)  
**Status:** bring-up complete 2026-11-18 (first inference verified; not yet a serving endpoint)

---

## Specifications

| Component | Spec |
|-----------|------|
| CPU | AMD Ryzen 7 7745HX (Zen 4 mobile, 35 W) — **8 cores, 16 threads**; measured 4.76 GHz single-core turbo under load |
| RAM | 48 GB DDR5-5200 (2×24 GB) |
| GPU | NVIDIA GeForce **RTX 3060 12 GB** (ASUS PH-RTX3060-12G-V2, GA106): compute 8.6, 36 SMs = 3,584 CUDA cores, 192-bit GDDR6 |
| PCIe | Gen4 x16 slot; **engine-measured 26.8 GB/s host→device** in the Strata PCIe probe under load (drops to a Gen1 x16 link while idle — normal power management, the same behaviour the Pascal laptop notes) |
| Storage | Samsung 512 GB M.2 NVMe (part MZALQ512HALU), single root partition (btrfs, ~460 GB usable) |
| Power | AC only; **S5 wake-on-LAN verified end-to-end** (magic packet → full boot in ~60–90 s), so the node can sleep after a window and be woken remotely |
| Network | headless; wired ethernet (static address) |
| OS | **NixOS 26.11 (flakes)**, kernel 6.18; the whole stack is declarative, including the engine build (below) |
| Driver / toolkit | NVIDIA **595.104.02** (open kernel module) + **CUDA 13.0** — taken from nixpkgs' `cudaPackages_13_0` (the merged toolkit prefix plus the individual components), not from a vendor package or an image layer |

## The engine build is a NixOS derivation

Strata v0.1.41 is built from the upstream git tag, not the project's `setup.py`
installer (which the lab's supply-chain notes treat with caution). The build is a
flake package that:

- compiles the CUDA side against nixpkgs' **CUDA 13.0** (`cudaPackages_13_0`: the
  merged `cudatoolkit` prefix is what `find_package(CUDAToolkit)` wants, plus
  cudart/crt/cublas/cccl as named components),
- links the engine against the driver **stub** (`libcudart`/driver dev stubs) and
  resolves the real `libcuda.so.1` at runtime from the OS-managed driver directory,
  so the binary is not coupled to one driver store path,
- builds the **CPU side natively on the box** (the engine's own Dockerfile says
  "build it on the PC it runs on") — so the result is correct for this CPU but is
  not reproducible on another builder, which is deliberate here,
- targets **sm_86 only** (the 3060), not the project's default five-arch set
  (that fat set exists for multi-vendor container images),
- pins the project's llama.cpp dependency to the exact commit its own tooling
  fetches.

Two CMake traps are worth recording for anyone building this project under a
package manager: the automatic "cmake" build hooks of a NixOS stdenv run their
own configure pass before a custom build phase (and with none of your flags), and
the project's `set(STRATA_GGML_DIR "" CACHE PATH …)` line silently clobbers a
value passed with `-D` (an untyped cache entry) — the working invocation pre-seeds
a typed `CMakeCache.txt` entry instead.

## Notes

- **The 40 GB expert arena streams at ~1.2 GiB/s off this NVMe** (measured during
  the arena fill: 39.97 GiB in ~33 s). That is the number a campaign's cold-I/O
  cells will see; the arena's pages are clean file cache, so the kernel reclaims
  them when an engine process exits and a fresh process re-reads the file —
  "warm" for this model means a *living* process, or a back-to-back start.
- 48 GB of RAM holds the 40 GB arena with only ~4 GB left for everything else;
  an always-on serve will want the engine's low-RAM/mmap modes (the same regime
  the backup box's 19 GiB page-locked budget runs in — see the model card), or
  a larger-disk/arena trade.
- The board has no case and no power button: the power input is a front-panel
  pin header (PWRBTN#/GND bridge) and the board does **not** auto-boot on power —
  after a power cut it needs a magic packet, not just the plug back in.
- No wall-plug meter on this node yet, so the numbers in the first-inference
  report carry no energy figures.
